# 摘要：Wiki 代替 RAG 的可行性评估

## 原始内容讲什么

本文是 Hermes Agent 对当前知识架构与 Karpathy LLM Wiki 方案的系统性对比分析。文章评估了当前架构在 Raw Sources 层、Wiki 层、Schema 层、Ingest/Lint/Query 操作等维度与 Karpathy 方案的差距，给出了能力矩阵评分（存储架构 6/10、分类体系 7/10、自动化 2/10、Schema 4/10、操作闭环 3/10），并提出了三阶段实现路径。

## 为什么值得迁移

- **系统性分析**：不是简单介绍，而是有评分、有差距分析、有实现路径的完整评估
- **决策参考**：在决定是否采用 Wiki 方案时可直接引用
- **与当前系统关联**：分析的是 Hermes 自身知识架构，有直接的改进指导价值
- **无来源 URL 的原创分析**：这是 Hermes Agent 的原创工作，具有独特价值

## 迁移后如何使用

- **架构决策参考**：在讨论知识库架构时引用评分和差距分析
- **路线图制定**：按 Phase 1/2/3 规划知识库改进工作
- **对比基准**：未来改进后可重新评分，量化进展
- **技术选型**：在 Wiki vs RAG vs 其他方案时作为内部评估案例

## 缺失信息或后续补充建议

- **更新评分**：每完成一个 Phase 后更新评分
- **补充实现细节**：可补充具体 skill 实现方案
- **成本估算**：可补充实现各 Phase 所需的工作量估算
- **对比扩展**：可补充与其他知识管理方案（如 Notion、Obsidian）的对比
