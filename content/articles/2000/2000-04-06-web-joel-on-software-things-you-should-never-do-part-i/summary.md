# 摘要：Things You Should Never Do, Part I

**作者**：Unknown
**来源**：Joel on Software

## 一句话总结

Joel Spolsky 反对轻易从头重写软件，认为旧代码里积累了大量隐性知识、bug 修复和真实用户经验，重写往往会让团队丢掉这些资产。

## 文章核心问题

当一个系统的旧代码看起来混乱、难懂、令人沮丧时，团队是否应该推倒重写？

## 主要观点

- 旧代码之所以丑，往往是因为它处理过大量真实世界的边界情况。
- 从头重写会丢掉多年积累的 bug 修复和用户行为知识。
- 重写期间产品通常无法持续改进，竞争者却可以继续前进。
- 更稳妥的路径通常是渐进式重构、局部替换和持续改良。

## 论证结构

1. 以 Netscape 重写浏览器的历史案例切入。
2. 解释程序员为什么容易讨厌旧代码。
3. 指出旧代码包含隐性经验和真实问题修复。
4. 反对大爆炸式重写，强调演进式改进。

## 关键概念

- rewrite from scratch
- legacy code
- hidden knowledge
- incremental refactoring
- opportunity cost
