# 先预检，再解读 YouTube 视频

## 为什么 YouTube 视频入库前需要预检

当你看到一个 YouTube 视频链接，第一反应可能是"解读它"。但在动手之前，有一个关键问题：**这个视频真的能被处理吗？**

YouTube 上的视频状态复杂多变：
- 有些视频已删除，链接成了死链
- 有些设为私密，外人无法访问
- 有些受地区限制，某些国家无法观看
- 有些需要登录或年龄验证
- 有些没有字幕，解读成本剧增

如果不预检直接开始解读流程，可能会浪费大量时间在不可处理的视频上。更危险的是，为了"强行"处理，可能会违反安全边界（登录账号、读取 Cookie、绕过限制）。

**预检的意义：在投入资源前，先判断视频是否值得处理。**

## 哪些失败不应该继续跑

| 失败类型 | 说明 | 是否可恢复 |
|---------|------|-----------|
| **视频已删除** | 链接指向不存在的视频 | ❌ 不可恢复 |
| **私密视频** | 需要视频所有者授权 | ❌ 不可恢复 |
| **地区限制** | 视频在部分地区不可用 | ⚠️ 可能可恢复（换网络） |
| **需要登录** | YouTube 要求登录验证 | ❌ 不登录 |
| **年龄限制** | 需要年龄验证 | ❌ 不登录 |
| **无字幕** | 视频没有字幕 | ⚠️ 可能可恢复（音频转写，但默认不启用） |
| **直播未开始** | 直播预约但尚未开始 | ⏰ 等待后可恢复 |

**核心原则**：不登录、不读 Cookie、不下载完整视频、不绕过限制。

## 为什么失败也要归档

失败不是终点，而是知识。

当一个视频预检失败时，归档记录：
- **什么时候失败的** — 避免重复检查同一链接
- **为什么失败的** — 区分技术问题（网络）和内容问题（删除）
- **尝试过什么** — 记录已验证的方法
- **安全边界是否遵守** — 证明没有违规操作
- **后续建议** — 为用户提供替代方案

这些归档形成一个"失败知识库"，帮助：
- 避免重复浪费时间在已知失败链接上
- 分析失败模式（某类视频经常不可访问？）
- 改进预检逻辑（发现新的失败类型）
- 为用户提供更好的失败反馈

## 它和 v0.3.19 / v0.3.20 的关系

```
v0.3.19: 一键入库命令能力建设
  │
  └── youtube-kb-import: 把视频知识包加入知识库

v0.3.20: 首次实战试运行
  │
  ├── Dario Amodei 视频: 成功入库
  └── U9Im71aNhYu: 失败（不可访问）

v0.3.21: 预检与失败归档能力建设
  │
  └── youtube-preflight: 在入库前先判断视频是否可处理
```

**v0.3.21 不是替代 v0.3.19/20，而是前置增强。**

以后的使用流程：
1. 用户提供一个 YouTube 链接
2. **先运行 youtube-preflight** — 判断可访问性
3. 如果 PASS — 继续 youtube-kb-import（v0.3.19/20 能力）
4. 如果 BLOCKED — 生成失败归档，停止流程

## 对个人知识库的价值

### 时间节省
避免在不可处理的视频上浪费 30-60 分钟的解读时间。

### 安全合规
预检机制强制执行安全边界，防止为了"完成任务"而违规操作。

### 知识积累
失败归档本身就是知识资产。它记录了你尝试过的链接、失败原因、替代方案。

### 流程标准化
把"先判断再动手"变成自动化流程，减少人为判断失误。

## 可访问视频和不可访问视频分别怎么处理

### 可访问视频（PASS）

```
youtube-preflight ──PASS──→ youtube-kb-import ──→ 视频解读 ──→ KB 入库
```

### 不可访问视频（BLOCKED）

```
youtube-preflight ──BLOCKED──→ failure archive ──→ 返回失败原因 + 替代方案
```

**替代方案**：
1. **提供可访问链接** — 如果同一视频有其他链接
2. **Notes-first import** — 如果用户有字幕/文字稿
3. **其他平台** — 如果视频在 Bilibili、Vimeo 等有镜像
4. **放弃** — 如果确实无法获取
