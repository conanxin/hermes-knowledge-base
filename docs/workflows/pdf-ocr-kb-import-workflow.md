# Local PDF OCR KB Import Workflow

> **Workflow ID**: `pdf-ocr-kb-import-workflow`
> **Status**: Active since v0.3.62
> **Required docs**: `docs/import-recipes/PDF_OCR_LOCAL.md` (MUST load first)
> **Companion command**: `docs/commands/pdf-ocr-kb-import-command.md`
> **Companion prompt template**: `templates/prompts/import_pdf_ocr_prompt.md`

## Purpose

End-to-end workflow that takes a local PDF file path and produces a
fully translated knowledge-base entry, with OCR report, per-file
`git add`, push, and live smoke. This workflow is the implementation
detail behind the `pdf-ocr-kb-import` command.

## Input

- `{{PDF_PATH}}` — absolute path to a local PDF file on the user's
  machine. The user MUST supply the path. If the user does not,
  the workflow blocks (see §hard-stop).

Optional hints from the user:

- `{{CONTENT_TYPE_HINT}}` — e.g. "essay", "paper", "book-chapter"
- `{{TITLE_HINT}}` — pre-supplied title in English or Chinese
- `{{AUTHOR_HINT}}` — pre-supplied author name
- `{{PUSH_MODE}}` — default `commit_and_push`; alternative `dry_run`
  (write files + run quality gates but do not commit/push)

## Output

```
content/articles/YYYY/YYYY-MM-DD-<slug>/
├── metadata.yaml
├── source.md
├── translation.zh-CN.md
├── summary.md
├── notes.md

reports/pdf_ocr_import_YYYY-MM-DD-<slug>.md   # OCR evidence

site/items/YYYY-MM-DD-<slug>/index.html    # generated detail page

```

## Execution order

### Phase 0 — Preflight (mandatory, blocking)

```bash
cd ~/hermes-knowledge-base
git fetch origin
git pull --ff-only origin main
git rev-parse --short HEAD                # must equal origin/main
python3 scripts/check_release_tags.py     # recommended_next_minor
python3 scripts/check_task_preflight.py --planned-tag v0.3.N-pdf-ocr-<slug>
```

If preflight FAIL → blocked report at
`reports/pdf_ocr_local_import_blocked_<YYYYMMDD>.md`. Do not proceed.

### Phase 1 — PDF inspection (read-only)

```bash
PDF_PATH="<absolute path from user>"
test -f "$PDF_PATH" || BLOCKED
pdfinfo "$PDF_PATH" > /tmp/pdfinfo.out
pdftotext "$PDF_PATH" - | wc -c > /tmp/text-layer-bytes.out
```

Inspect:

- `Producer` — scanner origin; "Document Capture" → scanned
- `Pages`, `Page size`, `Encrypted`, `CreationDate` — capture to OCR
  report
- `pdftotext` byte count — see PDF_OCR_LOCAL.md §5 for branching

### Phase 2 — OCR (if text layer is empty)

```bash
mkdir -p /tmp/pdf-ocr-pages
pdftoppm -r 250 "$PDF_PATH" /tmp/pdf-ocr-pages/page -png
for p in /tmp/pdf-ocr-pages/page-*.png; do
    tesseract "$p" "${p%.png}" 2>/dev/null
done
```

If a page is unrecognizable, attempt recovery (PSM 1, denoise) before
declaring hard-stop. See PDF_OCR_LOCAL.md §6.

### Phase 3 — Author / metadata extraction

- From the OCR'd title page, the running header (e.g. `> 164 URSULA K.
  LE GUIN`), and the closing colophon, extract:
  - `title`, `title_zh`
  - `author`
  - `published_date`, `publication_year`
  - `source` (book/report name and page range)
- If any field is unrecoverable, follow PDF_OCR_LOCAL.md §10 rules
  (`unknown` string for `author`, `null` for `published_date`, etc.).

### Phase 4 — Entry directory creation

```bash
DATE=$(date -u +%Y-%m-%d)
SLUG="<derived from author/title>"
ITEM_DIR="content/articles/$DATE/$DATE-$SLUG"
mkdir -p "$ITEM_DIR"
```

### Phase 5 — File generation (in this order)

1. `source.md` — full OCR text, page-tagged, `[OCR疑似: ...]` flags
2. `translation.zh-CN.md` — full Simplified Chinese translation
3. `summary.md` — Chinese summary + key quotes + extension questions
4. `metadata.yaml` — schema-compliant (all required fields, `source_url_missing: true`, `source_site: "local-pdf"`)
5. `notes.md` — preflight/duplicate/blocked/OCR decisions + related entries
6. `source.local-ref.txt` — local pointer to the PDF
7. `reports/pdf_ocr_import_<DATE>-<slug>.md` — OCR evidence report

### Phase 6 — Quality gates (must all PASS)

```bash
python3 scripts/check_kb.py                  # integrity gate
python3 scripts/update_site.py               # 5/5 substeps
python3 scripts/check_pages_sync.py          # post-sync gate
python3 scripts/check_translation_residue.py # WARN-only
```

If `check_kb.py` or `check_pages_sync.py` FAIL → blocked. Do not commit.
If `check_translation_residue.py` reports **real** untranslated
prose (not just book titles / proper nouns) → fix forward. If only
allowlisted residue → continue with documented warning.

### Phase 7 — Commit + push (per-file add only)

```bash
# Per-file, no `git add -A` or `git add .`
git add content/articles/$DATE/$DATE-$SLUG/metadata.yaml
git add content/articles/$DATE/$DATE-$SLUG/source.md
git add content/articles/$DATE/$DATE-$SLUG/translation.zh-CN.md
git add content/articles/$DATE/$DATE-$SLUG/summary.md
git add content/articles/$DATE/$DATE-$SLUG/notes.md
git add content/articles/$DATE/$DATE-$SLUG/source.local-ref.txt
git add reports/pdf_ocr_import_$DATE-$SLUG.md
git add docs/data/catalog.json site/data/catalog.json
git add index/authors.md index/catalog.jsonl index/tags.md index/timeline.md
git add docs/items/$DATE-$SLUG/index.html
git add site/items/$DATE-$SLUG/index.html

git diff --cached --stat
git diff --cached --name-only
git -c user.email="<>" -c user.name="<>" commit -m "Add OCR PDF knowledge entry: <title_zh> (zh-CN)"
git push origin main
```

For versioned tasks, additionally:

```bash
git tag -a v0.3.N-pdf-ocr-$SLUG -m "Add local-PDF KB import: <title_zh>"
git push origin v0.3.N-pdf-ocr-$SLUG
```

### Phase 8 — Live smoke

```bash
curl -sI https://conanxin.github.io/hermes-knowledge-base/ | head -1
sleep 30
curl -s https://conanxin.github.io/hermes-knowledge-base/data/catalog.json \
  | python3 -c "import json,sys; d=json.load(sys.stdin); print(len(d),'records')"
curl -sI "https://conanxin.github.io/hermes-knowledge-base/items/$DATE-$SLUG/" | head -1
```

If the live catalog is still N (not N+1), the status is
`PENDING_CDN_SYNC` (not a FAIL). See PDF_OCR_LOCAL.md §21.

### Phase 9 — Reporting

Use `docs/REPORTING_TEMPLATE.md` 模板 3 (9 sections). Required fields
beyond the template's defaults are listed in PDF_OCR_LOCAL.md §22.

### Phase 10 — Postflight (versioned tasks only)

```bash
python3 scripts/check_task_postflight.py \
    --report-file reports/pdf_ocr_local_import_recipe_v0.3.N_<YYYYMMDD>.md \
    --profile auto
```

Postflight is **WARN-only**. If warnings appear, list them in the
final report; do not pretend PASS.

## Hard-stop cases

All hard-stops from `docs/import-recipes/PDF_OCR_LOCAL.md` §18 apply.
In addition:

- **No PDF path supplied** — the user must provide a path. If the user
  only says "analyze this PDF" without supplying a path, the workflow
  blocks; do not guess.
- **User only says "analyze" / "summarize"** — this workflow does not
  apply. Use a read-only analysis path; the result goes into a chat
  reply, not into the knowledge base.
- **No `{{PDF_PATH}}` variable resolved** — same as above.
- **Multi-agent push collision** — see "Concurrency" below.

## Concurrency

Multi-agent shared repo. If `git push` is rejected with
"Updates were rejected because the remote contains work that you do
not have locally":

1. `git fetch origin`
2. `git reset --hard origin/main` (this drops your unpushed commit; do
   NOT use `git pull --rebase` which can lose work)
3. **Re-run Phase 5** (regenerate the entry files from the OCR text you
   already have; do not re-run OCR)
4. **Re-run Phase 6** (rebuild catalog from `update_site.py`)
5. **Re-run Phase 7** (commit + push)

This is the team's "reset-and-rebuild" convention; do not force-push.
The OCR text and translation live in your conversation context — you do
not need the old commit to recover them.

## PASS / PARTIAL / BLOCKED judgment

| Status | When | Required report |
|---|---|---|
| **PASS** | All 6 quality gates PASS, push succeeded, live smoke shows N+1 records, no warnings worth listing | 模板 3, no PENDING_CDN_SYNC |
| **PARTIAL** | Push succeeded, live catalog still N (CDN lag), or `check_translation_residue.py` emits only allowlisted warnings | 模板 3 with `PENDING_CDN_SYNC` annotation |
| **BLOCKED** | Any hard-stop in PDF_OCR_LOCAL.md §18 triggered, preflight FAIL, push rejected after retry, or any quality gate FAIL | 模板 1 (3 sections) at `reports/pdf_ocr_local_import_blocked_<YYYYMMDD>.md` |

## Live verification rules

- The home page and the new item page must return HTTP 200.
- The live catalog must show N+1 records (compared to the pre-import
  count). If it does not, the status is `PENDING_CDN_SYNC`.
- The detail page's HTML must be byte-identical between
  `docs/items/.../index.html` and the live URL. If not, run
  `python3 scripts/sync_pages_docs.py` and re-verify.
- 5-piece check (per memory note): HTTP 200 + `Cache-Control: max-age=300`
  header + real `site/` content (not a 4KB placeholder) + sustained
  for ≥ 2 polling rounds (T+0 and T+2min) + `gh api .../pages` returns
  `html_url` + `build_type=workflow`. The 5-piece check applies
  primarily to GitHub Actions-driven deploys; for a `git push` workflow
  the first 3 are sufficient.

## What this workflow does NOT do

- Does not modify `conanxin.github.io/projects/data.json`.
- Does not generate a standalone project page.
- Does not install new dependencies.
- Does not restart `hermes-gateway.service`.
- Does not send Telegram messages.
- Does not modify the Hermes Agent source code.
